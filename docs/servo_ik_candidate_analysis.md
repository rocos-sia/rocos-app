# 笛卡尔伺服 IK 连续性与限速器配合：逐周期诊断报告

日期：2026-11-06。主仓库基线 `bfc46de`，pin_ik `92e2d56185a843d48ade921809fa1fa681a34cf7`。这是对 `pin_ik_persistent_servo_test_report.md` 中未定位问题的追加诊断，不替换上轮数据。

## 结论

**大幅关节运动首先来自不连续的 IK 目标，随后被限速器逐步跟踪。** 当前选解策略只要求末端位姿满足容差，未要求关节解相对于上一周期连续；近奇异位形、Speed 提前结束搜索，以及使用限速后的关节参考作为 IK 初值，共同造成了本次复现。

这不是“每周期重新建线程”引起的现象。此次使用的是常驻工作线程版本；离线直接调用两个底层求解器，同一目标也能分别得到相距很大的有效解。限速器可以约束导数，却不能替 IK 判断一个远解是否适合作为下一周期的跟踪目标。

本轮仅增加默认关闭的诊断记录，没有修改求解策略、低通、限速、预算、保护阈值或 pin_ik 子模块源码。没有完成长期运动稳定性验收，也没有实施连续性修复。

## 记录内容与环境

新增 `src/servo_trace.hpp/.cpp`，通过 `ROCOS_SERVO_TRACE_DIR` 在创建处理器时启用。每次 `ServoSignalProcessor::Step` 记录：

- 周期序号、单调时钟、名义周期、低通系数、Step 总耗时、返回值和停止标志。
- 原始位姿 IK 与滤波位姿 IK 的目标、初值、公开候选集、候选分数、选中索引、后端返回值、求解耗时和候选复制耗时。
- 进入周期时的参考位置/速度/加速度、上一周期 IK 目标、送入限速器的目标、限速后参考及制动回退位。

控制线程通过预分配 SPSC 环形队列提交记录，独立写线程落盘。在线三轮共 **3919 条 Step 记录**，序号连续，丢弃数 0，写入错误 0；其中成功运动周期 3415、停止周期 503、失败周期 1。

只运行唯一一套原配置 App + MuJoCo，App PID 25309，MuJoCo PID 25274。保持单次 IK 1 ms、Speed 模式、低通 100 Hz、限速开启；名义周期 1 ms，配置加速度 10 rad/s²、jerk 150 rad/s³、减速度 10 rad/s²。普通笛卡尔 Step 仍然两次 IK。本轮不改变这个调用结构。

沿用上轮输入：各轴以本轮起点叠加幅度 0.01 rad、频率 0.05 Hz、相邻轴相位差 0.1 rad 的正弦，5 s 渐入，再通过 FK 生成笛卡尔位姿。FK 参数不是冗余 IK 的唯一正确关节解。第一轮从零位开始；第二、三轮从上一轮停止后的实际位置开始，未重新定位到零位，三轮并非相同初始条件。

三轮原计划各 10 s，实际均提前退出。测试端继续保留“实际或下发参考相对起点超过 0.1 rad 则请求停止”的条件。这是测试退出条件，不是机器人安全限位，也不是最终停止位置上界。Apifox 在线规范本轮已刷新并阅读；RCI/UDP v2 仍属于实现扩展，未写入在线规范，本轮未更新 Apifox。

## 根因证据

### 1. 近奇异位形下，极小的末端变化可以得到明显不同的关节解

第一轮周期 133：滤波目标相对上一周期 IK 目标的 FK，仅变化 **1.31 μm、1.33 μrad**；选中解相对当前限速参考的最大关节变化却是 **0.0132931 rad**。此时最大输出位置步长只有 **5.83e-9 rad**，说明异常关节目标出现在限速器之前。

该初值的几何 Jacobian 奇异值约为：

```text
2.075, 2.000, 0.479, 3.01e-9, 4.84e-10, 1.41e-10
```

它非常接近奇异位形。Jacobian 使用 URDF 独立计算，并与实际 `Model::GetJacobian` 对照，所有抽取样本最大元素误差 2.22e-16；FK 对照误差也为 2.22e-16。奇异值使用当前 m/rad 数值约定，只用于诊断病态程度，不是新的保护阈值。

pin_ik 的 Newton 路径在 `pinocchio_tl.cpp` 直接用完全正交分解求解 Jacobian 线性系统，然后累加 `delta_q`；当前路径没有阻尼或关节步长信赖域。关节限位处理并不等于限制每次迭代或每个伺服周期的关节变化。

### 2. 两个底层策略确实返回不同的有效解，Speed 未保证获得近解

App/MuJoCo 关闭后，直接复用两个底层求解器，对抽取的同一初值、同一目标各重复 100 次。保留 1 ms、1e-5 容差；Newton 保持随机重启及限位角度处理配置。以下每个数字在对应 100 次中相同，全部成功且通过独立 FK 残差检查：

| 在线样本 | Newton 最大关节变化 rad | NLopt 最大关节变化 rad |
|---|---:|---:|
| 第 1 轮周期 133，滤波位姿 | 0.0132931 | 0.0000076977 |
| 第 1 轮周期 608，滤波位姿 | 2.9554032 | 0.0002124341 |
| 第 2 轮周期 985，滤波位姿 | 3.0281162 | 0.0007464029 |
| 第 3 轮周期 940，滤波位姿 | 3.1023116 | 0.0005648585 |

这说明这些目标并不必然要求大幅关节运动。底层求解路径本身可以产生远解；同时也存在符合容差的近解。不能据此推导“NLopt 在所有轨迹都连续”，其他后期样本中 NLopt 也会产生远解。

当前 Speed 模式在找到解后提前结束并中止另一策略；最终只对已经收集的候选按 `JointErr(seed, candidate)` 排序。三轮中两候选的调用共 274 次，选中分数均为较小值，**未发现排序选错**。问题在于经常只收集到一个候选，近解没有进入可选集合。两候选策略也不等同于全局最近解搜索。

实际 Model 重复求解周期 133 样本，使用相同限速参考作为初值，100 次中 25 次变化超过 0.01 rad，其余返回约 7.70e-6 rad 的近解。并行完成顺序影响结果，与 Speed 的实现相符。在线公开候选集不含求解器来源标记，不能把每条在线记录严格归属到某个后端；底层对照证明了机制可复现。

### 3. IK 连续状态与限速状态混用，放大了两级处理之间的偏离

当前处理链为：

```text
上一周期 IK 目标 s.filtered → FK → 笛卡尔低通 → 本周期滤波位姿
                                              ↓
限速后的参考 s.q ───────────────────────────→ IK 初值
                                              ↓
                                      IK 目标 → 关节限速 → 新 s.q
```

`s.filtered` 保存未限速的 IK 目标，而下一次 IK 却以滞后的 `s.q` 为初值。当一次选中远解后，这两份关节状态可能相距数弧度；三轮记录中的最大初值/上一 IK 目标差为 2.9553、3.0282、3.1024 rad。下一周期会再次从限速状态求解，而非沿上一有效解延续，给近奇异区域的反复换解创造了条件。

对三轮“首次超过 0.01 rad”的滤波样本，改用上一周期 IK 目标作为离线初值，均为 **100/100 次返回原初值且满足目标容差**。它支持将连续 IK 状态与限速输出分开维护的方向，但不能视作充分修复：已经跳到远处的上一解会把错误位形保留下来；后期原始位姿样本也仍会有明显关节变化。需要同时约束选解连续性和目标/输出的偏离。

低通只平滑末端位姿，不约束冗余关节位形或近零空间运动；因此只保留笛卡尔低通也不能自动消除这些关节跳变。

### 4. 限速器按收到的目标工作，不能代替连续选解

将全部 **3415 个成功运动周期 × 7 轴 = 23905 次**限速调用，按记录的目标、进入周期时的位置/速度/加速度、dt 和当前限值离线回放：返回值全部成功，位置、速度、加速度与在线记录的最大差均为 **0**。在线成功运动周期没有触发制动回退。

所以本次“大幅运动”的直接解释是：IK 持续给出远近交替的目标，限速器以有限加速度和 jerk 追赶，速度及位移逐步积累。它没有把 3 rad 的候选瞬间原样下发。三轮运动阶段最大单周期位置步长分别为 0.000614、0.000980、0.000363 rad。

第二、三轮完整记录了 235、268 个停止周期（名义时长 235/268 ms，首末停止记录墙钟间隔约 251/286 ms）。停止过程仍额外移动最多 0.1390/0.1058 rad，最终参考速度和加速度均为零。含停止过程的最大参考速度分别为 1.0899/0.7263 rad/s；加速度不超过 10，jerk 不超过 150（仅约 3.4e-13 浮点尾差）。带着正加速度进入受 jerk 限制的制动时，速度还可能先上升，再减速。因此必须在进入大幅追赶之前检查 IK 连续性；0.1 rad 的测试退出条件不能保证最终停在 0.1 rad 内。

这些结果说明此次输出与当前限速算法一致，并不构成该算法在所有目标切换、位形或硬件上的完整稳定性/安全性证明。

## 本次 IK 失败的解释

第一轮周期 996 在**原始位姿 IK**失败：后端 -3、候选数 0、CartToJnt 墙钟耗时 **1060.273 μs**，Step 总耗时 **1085.064 μs**；第二次滤波 IK 未执行。这是预算窗口内未获得可接受解，不是选中后被限速器拒绝。

对相同目标与初值，关闭 App/MuJoCo 后使用实际 Model 和同样 1 ms 预算离线重复 100 次，**100 次成功**，求解耗时中位数 397.6 μs、最大 624.9 μs。因此不能把在线失败认定为目标几何不可达，也不能用它证明“1 ms 必然不足”。当时的求解路径、随机状态和工作线程调度与离线环境不同。现有记录只测到总墙钟时间，尚未拆分每个工作线程的 CPU 时间、等待时间及迭代次数，不能精确断言超时耗在哪一项。

即使求解成功，该失败样本的离线关节变化仍很大（最大轴变化至少约 0.205 rad）；延长预算并不能解决连续性问题。

## 修复方向（本轮未实施）

1. 为伺服保存上一有效 IK 解作为连续求解状态，同时保留限速输出作为实际可执行参考，禁止未通过连续性检查的远解更新前者。
2. 将关节距离/可执行增量纳入候选接纳条件，不能只依赖 Speed 在现有候选中的排序；不要简单换 Distance 就宣称解决，因为它也受预算和搜索范围限制。
3. 近奇异区域采用阻尼、信赖域/有界步长或明确的位形保持约束，避免无阻尼 Newton 将微小末端修正转换为大幅关节运动；保护参数应从型号、周期与导数限制确定，不能直接套用本报告的 0.01 rad 观察门槛。
4. 限制 IK 目标相对可执行参考的累积偏离，建立可解释的失败/停止路径；不应靠限速器慢慢追上错误的远解。
5. 用同一批捕获样本验证局部修复后，再在不同起始位形、近奇异和非奇异区域进行在线长测。更换初值的静态回放不是长期闭环稳定性证明。

- 正常运行未设置 `ROCOS_SERVO_TRACE_DIR` 时不创建记录队列或写线程。诊断时先创建有写权限的目录，再在启动 App 的环境中设置该变量；不要为开启诊断额外启动第二个 App。
- v1 是本机小端打包二进制，1685 字节/Step，最多记录 10 轴、每次 IK 最多 2 个公开候选；适用于本次非联动 Talon、Speed 模式。它不是 UDP/API 契约。其他模式可能返回更多候选，不能把截断的数据当完整候选集。
- 记录的是 `CartToJnt` 返回时的公开候选，而非内部每步迭代。首点单独验证发生在 Step 之外，本轮未记录那一次 IK。后端失败时，候选/输出字段不得作为有效解；未调用的 IK 返回值为 `INT32_MIN`。
- `solve_ns` 包含 CartToJnt 的工作线程等待，但不含 Model 入口互斥锁等待和后续 FK 检查；`elapsed_ns` 为 Step 范围时间。候选 getter 有复制/潜在分配开销，另记 `capture_ns`。
- 候选复制单次最大观测 41.812 μs；写线程、缓存访问和调度均可能扰动双策略竞争。带诊断的三轮与上轮无诊断试验退出时间不同，不能宣称无测量扰动，也不能用本轮估算稳定运行时间分布。
- 第一轮故障没有经过已记录的 Step 制动周期，后续故障处理不能由这份轨迹补全。第二、三轮则完整记录到了参考速度/加速度归零。
- 测试完成后关闭 RCI、下使能、确认 IDLE，再正常退出本轮 App 与 MuJoCo；两进程均已退出。未提交 Git，保留此前已暂存的子模块指针及 CMake 改动。
