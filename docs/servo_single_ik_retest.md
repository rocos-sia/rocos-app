# 单次 IK 修改与笛卡尔伺服复测

日期：2026-11-06。主仓库基线 `bfc46de`，pin_ik `92e2d56`，包含当前工作区诊断及本轮修改。原始证据位于 `build/servo_single_ik_retest/`。

## 修改范围

正常笛卡尔伺服周期改为：检查输入位姿合法性 → 笛卡尔位置/姿态低通 → 一次 IK → 关节限速和输出检查。移除了先对原始目标求 IK 的重复调用。

- 首点仍由 `MoveServo::validateStartReference` 独立求解并检查实际起点容差，超限拒绝。因此首周期合计仍有两次 IK：首点验证一次、正常 Step 一次；后续每个运动周期一次，停止过程零次。
- 保留原始输入的有限值、旋转正交性和行列式检查，防止低通处理非法位姿。后续周期不再提前求解未滤波目标来判断其可达性；若滤波后的目标求解失败，仍返回 IK 故障，不更新处理器参考状态。
- 保持 Speed、单次 1 ms 预算、限速后参考 `s.q` 作为初值、从上一 IK 解 FK 构建低通起点的原有行为。本轮没有实施独立位姿滤波状态、连续解初值或远解接纳约束，以隔离单次 IK 改动的影响。
- 低通、限速、通信保护及机器人配置均未改变；未修改 pin_ik 子模块源码、Apifox 或创建提交。
- 沿用逐周期诊断格式：槽 0 保留但不调用，槽 1 记录唯一一次滤波 IK。

## 构建与回归

单核执行：

```bash
cmake --build build --target rocosAppMain move_servo_test servo_robot_test servo_trace_test model_test --parallel 1
ctest --test-dir build -R '^(model_test|move_servo_test|servo_robot_test|servo_trace_test)$' --output-on-failure -j1
```

构建成功，四个套件全部通过，耗时 5.76 s。新增/更新的回归覆盖：

- 首周期包含独立首点验证，下一周期只增加一次 IK 调用。
- 位置和姿态先低通，求解器只收到滤波后的位姿。
- IK 失败不改变已接受的参考位置；非法旋转、非有限输入在求解前拒绝。
- 停止过程中不调用 IK；合法但超过起点容差的笛卡尔首点仍拒绝。
- 实际 Model 的诊断记录只包含槽 1 的候选，槽 0 始终为未调用状态。

## 逐周期结果

共保存 **13507 条 Step 记录**：12929 个运动/保持周期、578 个停止周期，零记录丢弃、零序号缺口、零写入错误。每个运动/保持 Step 都只有槽 1 的一次 IK，槽 0 从未调用；所有 Step 返回成功。独立首点验证在 Step 记录范围外，由回归测试检查调用次数。

| 运动用例 | 最大 IK/初值差 rad | 相邻 IK 目标最大变化 rad | 含停止过程最大参考位移 rad | IK 耗时中位数 / P99 / 最大值 μs |
|---|---:|---:|---:|---:|
| 运动 1 | 3.05261 | 5.67994 | 0.25719 | 91.9 / 405.2 / 824.7 |
| 运动 2 | 3.08498 | 3.14938 | 0.10836 | 109.9 / 265.7 / 360.6 |
| 运动 3 | 3.13937 | 3.13990 | 0.13796 | 70.0 / 209.7 / 407.7 |

三个运动用例的整个 Step 最大耗时分别为 865.0、400.6、426.9 μs。保持用例中仍观察到 IK 最大 1063.5 μs、Step 最大 1102.5 μs，且求解成功。因此单次调用并不等于硬实时保证，1 ms 求解预算也不是整个调用的严格墙钟上限。

独立 FK 验证所有成功候选的末端位置和姿态残差均小于约 1e-5 m / 1e-5 rad，但关节解仍有约 3 rad 的变化。含停止过程的参考加速度不超过 10 rad/s²，jerk 不超过 150 rad/s³（仅约 3.4e-13 浮点尾差）。这些是本次参考轨迹观测，不代表实际硬件完整安全性验证。

0.1 rad 是测试请求停止的触发条件，无法限制最终停止位置；运动 1 在受限制动后参考最大偏移达到 0.25719 rad。停止需要消除已经累积的速度、加速度。

## 判断与后续

**单次 IK 修改已生效，但没有消除大幅关节位形变化。** 本轮没有触发 IK 或通信故障，不能据这几个短时样本宣布相关问题已彻底解决。持续出现的远解说明：删除重复求解减少了工作量，但没有改变 Speed 的候选接纳、初值规则和限速器追赶远解的关系。

下一项应针对连续解状态与候选接纳做独立修改，再复用这些记录验证。不要通过放宽退出阈值或延长求解时间，把当前运动前置检查标为通过。与上一轮的退出时间不能直接解释为稳定性提升比例：双策略竞争、测量扰动和后续起点均不完全相同。

Apifox 在线规范本轮已刷新并阅读所用控制/伺服接口；RCI 和 UDP v2 仍是当前实现扩展，正式规范尚未覆盖。测试沿用已检查的实现行为，不改变契约。

测试后已关闭 RCI、下使能并确认 IDLE，再正常关闭本轮 App 与 MuJoCo；两个进程均已退出。证据包括 `build.log`、`tests.log`、`runtime_identity.json`、`online_suite.json`、`analysis.json`、`traces/`、各轮 UDP 原始文件和 `shutdown.json`。保留上一轮数据，未覆盖。
