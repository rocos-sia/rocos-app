# Talon 固定 jerk 非奇异姿态伺服测试流程与结果

本报告固定各轴 **J=10000 rad/s³**，使用指定非奇异姿态，对笛卡尔 UDP 伺服的一阶低通、单次 IK、逐周期关节限速及实际跟随进行验证。在线数据采集于 2026 年 11 月 8 日，本次整理补充了全部已记录正常周期的 Jacobian 复核。

在物理步长与控制周期均为 1 ms 的实验中，0.1～1 Hz 各完成 60 s。2 Hz 在 50.47 s、追加的 1 Hz 在 97.93 s 因关节累计偏移达到客户端范围限制而结束。3、5 Hz 触发反馈速度差保护。当前已验证的结果覆盖有限时长的非奇异邻域跟踪，高频持续运行和计划 300 s 长测仍未完成。

## 标准执行流程

### 准备与基线记录

1. 单核编译并完成离线回归，记录提交号、工作区修改、App 与动态库哈希。将固定 J=10000 的测试结果单独列入基线表，同时保留完整回归结果。
2. 为每轮创建新结果目录，保存启动配置、有效配置、模型和客户端哈希。在线过程保存原始指令、状态包和逐周期 IK trace。
3. 确认有效参数中的各轴 J=10000、A=10、V=3，低通与限速开启，截止频率为 100 Hz。
4. 显式加载 1 ms 物理模型，并验证 `mjModel.opt.timestep` 和单次 `mj_step` 的时间增量均为 0.001 s。主站声明周期和客户端发送周期均为 1 ms。
5. 确认唯一 App、MuJoCo 和它们使用的共享内存。保存初始 `IDLE`、位置控制模式和单位工具偏置。

原仿真仓库的默认模型仍使用 2 ms 物理步长。本轮已验证的 1 ms 模型位于测试目录，复测时应显式选择它或具有同等设置的模型。[1 ms 启动配置](/home/rocos/Documents/GitHub/rocos-app/build/servo_franka_limiter_20261108/online_1ms/mujoco.yaml) · [步长实测](/home/rocos/Documents/GitHub/rocos-app/build/servo_franka_limiter_20261108/online_1ms/timestep_check.txt)

### 定位与轨迹输入

1. 获取控制权，使能并显式定位到固定起点。保存目标、实际位置、工具偏置和 Jacobian 奇异值。
2. 开启 RCI，创建新的控制会话，保存会话标识和序号。发送与起始实际位姿一致的首点。
3. 先执行 5 s 保持测试，核对参考、实际反馈、通信质量和停止结果。
4. 依次执行 0.1、0.25、0.5、1、2、3、5 Hz，每档请求 60 s，每档开始前重新定位。
5. 对完成 60 s 且无故障的最高频率追加 300 s。本轮该频率为 1 Hz。
6. 每档结束后保存日志与最终状态。故障用例保存故障快照和停止过程，恢复到可定位状态后开始下一档。

正弦轨迹固定为下式，`t` 使用客户端单调时钟经过的秒数。

\[
g(t)=\sin^2\left(\frac{\pi}{2}\min\left(\frac{t}{5},1\right)\right)
\]

\[
\begin{aligned}
x(t)&=x_0+0.010g(t)\sin(2\pi ft),\\
y(t)&=y_0+0.005g(t)\sin(2\pi ft+\pi/2),\\
z(t)&=z_0+0.0025g(t)\sin(2\pi ft+\pi/4).
\end{aligned}
\]

位置单位为米，姿态保持起始值。前 5 s 为幅值渐入阶段。升频改变正弦频率，UDP 发送频率固定为名义 1 kHz。

### 结束条件与结果判定

| 条件 | 记录与判定 |
|---|---|
| 达到请求时长，故障为零，停止完成 | 该工况持续运行完成，单独报告精度指标 |
| 控制器报告故障 | 保存故障码、相关轴、触发值、阈值、制动过程和最终状态 |
| 实际或最终下发关节位置相对起点超过 0.1 rad | 客户端结束该档，记录累计偏移；持续运行目标未完成 |
| 连续 100 ms 无有效 UDP 回包 | 客户端结束并保存最后收到的状态及停止结果 |
| 日志丢记录、模型步长不一致或数据对齐失败 | 标明受影响的统计范围，完成数据核验后再作该项结论 |

0.1 rad 是本测试客户端的运行范围阈值。机器人还独立执行位置边界、导数限制、跟随误差、通信和制动可行性保护。正常结束验证 `STOPPED`，故障结束验证故障被保留并完成停止。每轮最后关闭 RCI、下使能到 `IDLE`、释放控制权，关闭本轮启动的进程。

持续运行完成、精度达到应用目标、保护正确执行分别记录。本轮精度报告采用实测值，应用所需的最大 TCP 误差尚未给定。

### 数据对齐与指标

- 以 `cycle` 去重，以 `applied_message_id` 对齐原始命令，以相同参考值与采样时间对齐 IK trace。
- 保存原始命令、滤波位姿、IK 候选解、最终限速参考及其速度和加速度、最终下发值、实际反馈、故障与单调时间戳。
- 位置误差计算三维欧氏距离，报告 RMS、P99 和最大值。峰值采用全部对齐记录，绘图允许降采样。
- 正常跟踪与停止过程分别统计。停止过程检查制动参考的导数约束及最终速度、加速度。
- 墙钟时间同时统计 IK 调用、整个处理 Step、控制周期间隔及客户端发送间隔。预算配置与实测耗时分别保留。
- 每档复核全部已记录正常周期的 Jacobian，保存 IK 目标、限速参考和实际反馈的最小奇异值与最大条件数。
- `control_command_success_rate` 按当前实现表示控制周期获得新命令的比例。驱动执行情况通过实际反馈和最终输出另行检查。

本报告的 TCP 总误差相对于该周期已应用命令。最新发送目标相对已应用命令的通信年龄需要独立统计。阶段误差峰值发生时刻不同，应使用同一时刻的向量分解分析峰值贡献。

## 限速方案更换的效果

当前笛卡尔输入经过一阶低通和单次 IK，再用上一接受的关节位置、速度、加速度约束本周期输出。其限速递推对应 libfranka 的标量关节位置函数，ROCOS 额外执行位置相关速度包络、jerk 区间交集、不可行拒绝和制动检查。[Franka 限速实现](https://raw.githubusercontent.com/frankarobotics/libfranka/main/src/rate_limiting.cpp)

一阶低通采用 `α=h/(h+1/(2πfc))`，本轮 `α≈0.38587`。位移递推与四元数 SLERP 使用同一系数。[Franka 低通实现](https://raw.githubusercontent.com/frankarobotics/libfranka/main/src/lowpass_filter.cpp)

修改前后对照均使用当时相同的原仿真配置，J=10000、A=10、V=3、低通 100 Hz。为使峰值可比，采用修改前故障发生前的相同时间前缀。

| 阶段 | 延迟 ms |
|---|---:|

限速参考相对 IK 目标的基频附加延迟约 0.013 ms，实际反馈相对限速参考约 27.249 ms。基频拟合描述稳态相位，短时速度波动仍需看逐周期记录。[稳态拟合](/home/rocos/Documents/GitHub/rocos-app/build/servo_franka_limiter_20261108/phase_1ms.json)

一阶低通在低频的理想延迟约为 `1/(2πfc)=1.592 ms`。控制递推使用 1 ms，实测墙钟周期间隔中位约 1.08 ms，这与本轮约 1.73 ms 的低通延迟相符。

幅值为 B、频率为 f 的正弦经过纯延迟 τ 后，同轴误差幅值为

\[
E=2B\left|\sin(\pi f\tau)\right|.
\]

代入 B=10 mm、f=1 Hz、τ=28.994 ms，X 方向约为 1.819 mm。XYZ 合成和短时波动对应本轮约 2.004 mm 的三维峰值。当前实际控制链的跟随滞后占据主要位置误差。

## 时间尺度与实时性

原模型每次 `mj_step` 推进 2 ms，而主站每周期只调用一次物理步进并声明 1 ms。速度反馈按物理秒产生，参考导数按控制递推周期产生。原 1 Hz 数据中，UDP 速度反馈相对位置墙钟变化率的拟合比例约 0.540，与约 1.08 ms 墙钟循环除以 2 ms 物理推进相符。
