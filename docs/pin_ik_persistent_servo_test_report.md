# pin_ik 常驻线程版本：笛卡尔伺服长测前置验证报告

日期：2026-11-06。主仓库基线 `bfc46de`；pin_ik 更新至 `92e2d56185a843d48ade921809fa1fa681a34cf7`，App 的 CMake 已补入 `worker_thread.cpp`。

## 结论

**未完成 30 分钟笛卡尔运动稳定性验收。** 三次笛卡尔保持均完成 60 s，并正常停止；三次小幅运动均在 0.845–0.887 s 触发测试客户端的关节位移退出条件，主动停止。运动前置检查没有通过，因此没有进入计划的 1800 s 阶段。

本次不是机器人报 `IkCalcFail`、通信故障或必要运动约束违规而退出：六次控制器故障码均为 0，主动停止前为 SERVOING，停止后均为 STOPPED。这与早期版本的 IK 报错退出必须区分。**常驻线程解决了反复建线程的问题，但当前集成仍出现相对于小幅输入较大的关节位形变化。**

## 环境与配置

- 本轮只测试，没有修改业务代码、pin_ik 源码、机器人配置或保护阈值，没有提交 Git。运行程序与源码哈希保存在 `runtime_identity.json`。
- 唯一 App PID 17271，唯一 MuJoCo PID 17242，双方确认映射 `/dev/shm/ecm_v2_0`。App 使用 `config/app.yaml`；仿真使用原 Talon MJCF 配置，名义周期 1000 μs、启用窗口。
- 单次 IK 显式预算为 1 ms，使用 pin_ik 默认 Speed 双求解器和常驻工作线程。当前分支的普通笛卡尔周期仍调用两次 IK，首周期另外做一次原始首点检查；本轮没有改成之前试验的同步单线程路径，也没有恢复其他试验改动。
- 低通和限速均开启，低通截止频率 100 Hz；通信保护保持原设置。App 没有显式配置新 IK 工作线程的亲和性或实时调度。本轮初始化快照中的 App 线程使用普通调度，客户端采用 SCHED_FIFO 30。
- App 单核构建成功；沿用刚完成的 model_reference、model、move_servo、servo_robot 四个回归套件全通过结果。客户端重新编译，并检查 UDP 状态/命令结构大小为 1096/236 字节。运动期间没有编译、离线压测或 strace。
- Apifox 在线规范已于本轮刷新并阅读相关接口。RCI 路由及 UDP v2 扩展仍未收录到正式契约，测试依据已检查的实际实现使用这些扩展，未更新 Apifox。

## 方法与退出条件

沿用之前的输入公式：各轴以本次起点叠加幅度 0.01 rad、频率 0.05 Hz、轴间相位差 0.1 rad 的正弦，经 5 s 平滑渐入后，用实际 Talon Model 的 FK 转换为笛卡尔位姿。活动工具为单位变换，客户端按绝对时间以 1 kHz 发包。FK 的关节参数仅用于生成目标，不是要求冗余 IK 必须返回的唯一关节解。

计划为 60 s 保持 → 60 s 小幅运动 → 两者通过后执行 1800 s 连续运动。若前置检查未通过，则重复保持/小幅运动到各三次。每轮从停止后的当前位置建立新会话，没有将机器人搬回最初零位。

鉴于此前测试出现大幅位形漂移，本轮客户端在任一实际关节位置或最终下发参考相对本次起点超过 **0.1 rad** 时请求 `rci/stop`。这是本次小幅轨迹测试的提前退出条件，**不是机器人型号的必要安全限位、不是末端误差判据，也不保证最终停止位移小于 0.1 rad**。它限制了本次能观察到的后续行为，不能据此次提前停止判断机器人之后一定会或不会报错。

客户端先停止再整理统计，避免收尾统计造成真实断流。停止请求后查询状态，确认 STOPPED；记录原始命令、UDP 状态、最终 HTTP 快照和诊断日志。

## 通信、线程与快照质量

- 六次测试故障位全部为 false。三次运动退出时新指令比例均为 1.00；保持阶段最低窗口比例分别为 0.95、0.98、0.96。`control_command_success_rate` 是新指令可用比例，不是驱动执行成功率。
- 六次命令和状态异步日志丢弃均为 0。检查同周期关键字段不一致、周期倒退、采样时间倒退、applied_message_id 大于 received_message_id，均为 0。
- 相邻控制快照采样间隔的中位数约 1.069–1.072 ms，最大观测 2.136 ms；名义周期仍为 1 ms。这是快照时间差，不是单次 IK 耗时，不能据此拆分求解器内部耗时。
- 5 s 间隔资源采样共 37 次，均采到 SERVOING；App 总线程数稳定为 43，RSS 为 22484–23608 kB。42 个线程 ID 在所有采样中保留，另一个槽位随 UDP 会话变化。采样可能漏掉瞬时事件；结合此前独立 Model 的 2 万次调用及系统调用跟踪，支持 IK 工作线程被持续复用的结论。
- 诊断日志查询返回事件为空。本次没有真正触发机器人故障，因此只验证了正常停止和状态保留，没有重新验证 IK 故障终态交付或故障恢复。

## 解释与后续定位

本轮直接证据是：保持可连续运行，小幅笛卡尔输入下出现较大的关节位形变化，且这种变化没有伴随通信故障。冗余机器人同一末端位姿可以对应不同关节配置，不能单凭关节参数差就判定某次 IK 数学错误；但当前行为没有满足本次小幅轨迹试验的退出要求，不能宣称长时序稳定性已通过。

当前仍存在的集成事实是：常规周期两次 IK、默认 Speed 候选策略，以及以限速后的关节参考为求解初值。需要记录原始/滤波目标、两次 IK 的初值与候选解、求解器选择和分段耗时，进一步区分解分支变化与限速跟踪的作用。本次没有记录这些内部数据，不能将根因断言为某一个求解策略，也不能认为再次修改线程生命周期即可解决。

保持测试的结果优于早期每次创建线程版本中数秒内失败的观察，但这是不同版本与运行条件下的有限样本，且本次新增测试端退出条件；不能直接比较运动故障发生时间，也不能替代计划中的 30 分钟验证。本轮没有降低保护阈值或延长 IK 预算来继续测试。
